# LTEE Project

## What is this project about?

Variant calling on three *E. coli* clones from the Long-Term Evolution
Experiment (LTEE), with a sensitivity analysis of the minimum-read-depth
filter (depths 2, 5, 10 and 15). The same pipeline is implemented as a shell
script, Snakemake and Nextflow, and the three give identical variant calls.
Everything is rebuilt from the raw reads with one command.

Author: Jenna Khanfar (ORCID 0009-0008-1641-5960)

## Is there a related publication?

No publication of its own. The data come from the LTEE; the main reference is
Tenaillon et al. 2016, *Nature* 536:165-170,
[doi:10.1038/nature18959](https://doi.org/10.1038/nature18959). The analysis
follows the Data Carpentry *Wrangling Genomics* lesson.

## Reproduce the results

You need [Pixi](https://pixi.prefix.dev/latest/) and an internet connection.
Then, from this folder:

```bash
pixi install          # builds the exact environment recorded in pixi.lock
pixi run reproduce    # downloads the raw data and rebuilds every result
```

`pixi run reproduce` must work on a fresh clone of this repository. A GitHub
Action (`.github/workflows/reproduce.yml`) checks that on every push.

Each folder has its own `README.md` with more detail.

## Hardware

Measured on a MacBook Air (Apple M4, 10 cores, 24 GB RAM, macOS), starting
from a fresh clone with the environments already installed (`pixi install --locked`):

| Step | Wall time |
|------|-----------|
| `pixi run reproduce` (download, QC, Snakemake pipeline, report) | about 3 min |
| `pixi run compare-workflows` (Nextflow run and comparison) | about 1 min |

Peak memory was about 0.4 GB. Disk use is about 3.7 GB for the Pixi
environments, 350 MB for `data/` and 200 MB for `results/`. Any 64-bit Linux or
macOS machine with 4 GB RAM and about 5 GB of free disk should be enough.
Times exclude the one-off download of the Pixi environments on a machine that
has never run it.

## Outputs

After `pixi run reproduce`, in `results/` (not committed):

- `qc/`: FastQC and MultiQC quality reports for the reads.
- `bam/`, `bcf/`: alignments and raw variant calls.
- `vcf/*_final_variants.vcf`: the final filtered variants per sample
  (SRR2584863: 25, SRR2584866: 775, SRR2589044: 10).
- `sensitivity/`: variant calls at depth filters 2, 5, 10 and 15.
- `stats/`: alignment and variant statistics.

The report `reports/ltee-report.html` is rendered from
`reports/ltee-report.qmd`, with every number and figure computed at render
time. `pixi run compare-workflows` checks that Snakemake and Nextflow agree.

## Data

Raw reads: trimmed and subsampled LTEE reads prepared by Data Carpentry,
from [figshare](https://doi.org/10.6084/m9.figshare.7726454)
(`sub.tar.gz`, CC0). The original runs are in NCBI BioProject PRJNA295606:
SRR2589044, SRR2584863 and SRR2584866.

The reference is *E. coli* B str. REL606, NCBI assembly
GCA_000017985.1_ASM1798v1.

From the project folder, run `pixi run download` to download the raw files,
verify their checksums and make them read-only. Download URLs and provider
MD5 checksums are in `metadata/sources.tsv`; SHA-256 checksums of the stored
files are in `metadata/checksums.sha256`. Sample descriptions are in
`metadata/samples.tsv`.

## Data and code availability

The raw reads are public (figshare, CC0; original runs in NCBI BioProject
PRJNA295606) and are downloaded and checksum-verified by `pixi run download`.
No raw data are stored in this repository. All code is in this repository and
is archived on Zenodo with a DOI (see the badge above and `CITATION.cff`).
The data contain no sensitive information.
